# AI_CREDIT_USAGE_PLAN.md - AI 크레딧 사용 정책 계획

> 최종 갱신: 2026-07-08

## 목표

Gemini API 비용을 사용자가 체감 가능한 단위의 크레딧 정책으로 제한한다. 무료 사용자는 광고 시청으로 크레딧을 충전하고, 유료 플랜 사용자는 크레딧 UI와 차감 흐름을 보지 않게 한다.

## 크레딧 사용

| 기능 | 차감 |
|---|---:|
| AI 채팅 1회 전송 | 1크레딧 |
| 이전 문자 기록 월 데이터 가져오기 | 월 1개당 1크레딧 |

채팅은 질문 유형별 차등 과금보다 사용자가 이해하기 쉬운 1회 1크레딧으로 단순화한다. 과거 월 문자 가져오기는 월 단위로 실행되므로 월 데이터 1회 요청을 1크레딧으로 본다.

## 크레딧 충전

| 수단 | 충전 |
|---|---:|
| 보상형 전면 광고 1회 시청 | 2크레딧 |
| 유료 플랜 | 크레딧 미노출, 차감 없음 |

현재 1차 운영은 광고 충전 중심으로 둔다. 결제 기반 크레딧 패키지나 월 7,900원 유료 플랜은 Play Billing 검증, 환불/중복 지급 방지, 서버 검증 정책이 필요하므로 후속 작업으로 분리한다.

## RTDB 설정

```json
{
  "credit_ad_enable": true,
  "reward_ad_enabled": true,
  "reward_ad_chat_count": 2
}
```

- `credit_ad_enable`: AI 크레딧 UI와 차감/충전 게이트
- `reward_ad_enabled`: 보상형 광고/배너 광고 공통 게이트
- `reward_ad_chat_count`: 광고 1회 시청 시 지급할 크레딧 수

## 이번 반영 범위

1. 채팅 크레딧 정책을 1회 1크레딧으로 단순화한다.
2. 광고 1회 기본 보상을 2크레딧으로 맞춘다.
3. 이전 문자 기록 월 데이터 가져오기 경로에서 크레딧 1개를 차감한다.
4. 크레딧 부족 시 보상형 광고를 시청하고 2크레딧 충전 후 월 데이터 가져오기를 재시도한다.
5. 광고 로드/표시 실패 시 과거 월 데이터 가져오기가 우회 실행되지 않도록 막는다.
6. `ServiceTier.PREMIUM` 사용자는 크레딧 기능을 비활성으로 취급해 크레딧 UI와 차감 흐름을 숨기는 기반을 둔다.

## 후속 범위

- Play Billing 상품 `premium_monthly_7900` 설계
- 결제 토큰 서버 검증
- 프리미엄 구독 상태와 `ServiceTier.PREMIUM` 동기화
- 유료 플랜 소개/구매 UI
- 구독 취소/환불/만료 시 FREE 복귀 정책
