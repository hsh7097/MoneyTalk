# Agent Worklog Decisions

> 기준: 흡수된 AI 경험/검색 최적화 worklog 원문을 KB용으로 재작성

## AI 경험 개선 결정

| 결정 | 상태 | 이유/영향 |
|---|---|---|
| 기본 기록/분류/홈/가계부 통계는 무료 경쟁력으로 유지 | 유효 | 핵심 사용 흐름을 과금으로 막지 않는다. |
| 채팅 기능은 즉시 삭제하지 않고 보조 진입점으로 낮춘다 | 유효 | 세션/뒤로가기/사용자 데이터 영향이 커서 화면 구조 변경 전 검증 필요 |
| AI 체감은 사용자가 질문을 쓰는 방식보다 앱이 먼저 제안하는 인사이트/정리 카드에서 만든다 | 유효 | 로컬 집계 기반 카드가 Gemini 비용을 줄일 수 있음 |
| 전면/리워드 광고를 사용 흐름을 막는 기본 수익화 축으로 삼지 않는다 | 부분 보류 | 현재는 크레딧 충전 수단으로 보상형 광고를 사용하지만, 답변 중간 광고는 피한다. |

2026-05-15 1차 변경은 AI 탭 문구를 상담/채팅 중심에서 인사이트 확인 중심으로 조정한 수준이다. 라우트, DB, `ChatViewModel`, 광고/AI 호출 로직은 변경하지 않았다.

## 검색/분류 최적화 결정

| 결정 | 상태 | 이유/영향 |
|---|---|---|
| HNSW/Redis/Python 인덱스는 도입하지 않는다 | 유효 | Android 단말 앱 구조와 맞지 않고 수치 병목이 확인되지 않았다. |
| DB/Gradle/ProGuard/signing config는 필요성이 검증되기 전까지 변경하지 않는다 | 유효 | 운영 리스크가 크다. |
| API 키가 없어도 로컬 사전 분류 규칙을 실행한다 | 완료 | Gemini 없이도 기본 카테고리 분류가 동작해야 한다. |
| 넓은 로컬 키워드를 벡터보다 앞당기는 변경은 보류한다 | 보류 | `자동납부`, `카드결제`, `푸드`, `식당` 같은 넓은 키워드가 오분류를 만들 수 있다. |
| 분류 계측 로그는 count-only로 제한한다 | 완료 | 가게명, SMS 원문, 금액 같은 민감 데이터를 남기지 않는다. |

## 후속 작업 기준

1. AI 탭을 더 줄이거나 카드 중심으로 바꾸려면 채팅 세션/뒤로가기/기존 사용자 데이터 영향부터 검증한다.
2. 검색/분류 최적화는 새 인프라보다 기존 tier의 호출 수, 오분류율, latency 계측을 먼저 본다.
3. 로컬 규칙 우선순위를 바꾸려면 golden dataset 또는 최소 회귀 테스트를 먼저 만든다.
4. worklog의 과거 계획이 현재 KB/코드와 충돌하면 현재 코드와 기능 KB를 우선한다.
