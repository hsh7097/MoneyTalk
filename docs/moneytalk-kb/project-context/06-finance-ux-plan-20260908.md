# 금융 UI 사용성 감사와 변경 판단

이 문서는 `600996a` 이후 금융 UI 정돈 작업의 판단 근거다. 현재 기능 계약은 [화면 요구사항](../screen-requirements/01-screen-requirements-index.md), 계산·데이터 범위는 [기존 제품 개선 검토](04-product-improvements-20260908.md)가 정본이다. 아래 제안과 후속 구현 대조를 구분하며 실제 빌드·검사·최신 캡처 상태는 [통합 검증 기록](07-finance-ui-validation-20260908.md)을 따른다. 경쟁 앱을 실제 계정으로 조작하지 않았으며, 공식 웹 자료를 현재 모바일 화면의 전체 배치나 성과 수치로 확대 해석하지 않는다.

## 공식 자료에서 가져온 원리

확인일: 2026-09-08. 브랜드 자산이나 고유 화면을 복제하지 않고, MoneyTalk의 기존 기능을 이해하기 쉬운 순서로 배치하는 데 참고했다.

| 공식 자료 | 확인한 내용 | MoneyTalk에 적용하는 판단 |
|---|---|---|

토스의 [2020년 소비 인터뷰](https://toss.im/tossfeed/article/toss-user-interview-timeline)는 날짜별 확인과 비교라는 사용 목적을 설명하지만, 본문 스스로 예시 화면·2019년 말 기준임을 밝힌다. 따라서 최신 앱 UI의 근거로 채택하지 않았다.

## 변경 전 코드에서 확인한 문제

| 높음 | `core/ui/component/transaction/card/TransactionCardCompose.kt`: 일반 지출 금액에 `colorScheme.error`, 카테고리·시간·카드·고정·통계 제외를 한 Row에 표시 | 모든 지출이 경고처럼 강조된다. 긴 메타데이터가 중요한 상태 표시와 경쟁한다. 지출은 중립색, 금액과 거래명 우선, 고정/통계 제외는 별도 상태줄로 보존한다. |

## 화면별 변경 기준

| 화면 | 정보와 행동의 순서 | 보존해야 하는 기능 |
|---|---|---|
| 홈 | CTA → 중앙 월 이동/기존 그라데이션 월 지출·수입 → 누적 차트 → 최근 소비 비교 → 고정 예상 → 카테고리 → 오늘 전체 내역 | 현재/전월 수집 안내, 차트의 동일 경과일/과거 전체·0원 비교, 주간 비교와 카테고리 이동, 오늘 합계·지출 건수·수정/삭제. 예산은 ‘내 소비 한눈에’에서만 제거하고 설정·계산·차트 토글 유지 |
| 내역 | 월/기간 → 지출·수입 합계 → 목록/달력 → 필터·검색·추가 → 날짜별 거래 | 검색은 기존 전체 기간 범위, 활성 필터 표시, 필터 재편집, 초기화, 수입/이체/통계 제외 정의, 롱클릭 메뉴 |
| AI 상담 | 질문하기 → 기존 대화 이어보기 → 방 안 질문 예시·입력 → 답변·재시도 | 서비스 불가 상태, 로딩 중 제출 차단, 크레딧/광고 표시 조건, 답변 한계 안내, 기존 세션 삭제 확인 |
| 설정 | 기존 섹션 순서를 유지한 제목·설명·행 → 상세 설정 | 월 시작일·예산·카드·권한·백업·복원·전체 삭제, 코치마크 위치, 기존 데이터 작업 확인창 |
| 상세/편집/관리 | 제목 → 주요 값 → 관련 입력/목록 → 완료 행동 | 원문·메모·고정·통계 제외·동일 거래처 적용, 오류 및 미저장 처리, 이미 존재하는 진입 계약 |
| 거래 롱클릭 | 대상명 → 수정 행 → 삭제 행 | 중앙의 작은 모달, 닫기, 수정은 기존 상세 편집, 삭제만 별도 이름·금액 확인, 한 번만 실행 |

기록된 지출 합계를 실제 계좌 잔액처럼 표현하거나, 다음 고정 지출의 추정 날짜를 확정 납기일로 바꾸지 않는다. 홈 Hero의 제목은 사용자 요청으로 원래 문구를 복원했으며 선택 연·월/기간과 차트 범례로 기간을 함께 확인한다. 카테고리 상세의 기간 중립 문구는 유지한다. 수입·유입·이체의 계산 정의를 통합하지 않는다.

## 기획·디자인 교차 검토

디자이너 제안은 밝은 중립 배경 `#F4F5F7`와 흰 표면, 다크 배경 `#14171B`와 표면 `#20252B`, 진한 초록 액션색 `#087F5B`다. 다크 액션은 `#6DDBB0`와 어두운 전경색을 짝지어 사용한다. 기본 제목 20sp, 본문 16sp, 보조 13sp와 화면 좌우 20dp를 기준으로 둔다. 이는 MoneyTalk용 제안값이며 경쟁 앱의 측정값이라고 주장하지 않는다.

기획 검토 결과, 총액·상태의 위계를 분리하는 방향에 동의했다. 요약·설정 그룹의 넉넉한 여백을 모든 거래 행에 동일하게 적용하면 한 번에 확인 가능한 내역이 줄어드므로, 거래 행은 밀도를 유지한다. 큰 글자에서는 거래명과 금액을 세로로 분리하고, 고정·통계 제외 표시는 숨기지 않는다. 억 단위 금액은 기본 글자 배율에서도 별도로 확인한다.

첫 검토에서는 브리핑 수치의 위계를 조정하고 기록 안내를 카드 하단에 표시하도록 권고했다. 이후 접힌 분석, 상단 통합 비교, 독립 큰 금액/보조 차트를 차례로 구현했지만 사용자는 최종적으로 기존 그라데이션 홈 복원을 요청했다. 이 요청을 우선해 홈 전용 테마·거래 카드·CTA로 원래 표현을 복원하고, 추가 요청대로 차트를 월 지출 바로 아래에 두며 ‘내 소비 한눈에’에서는 예산을 제거한다. 중립 공용 UI는 다른 화면에 유지한다. 이는 사용자 선호를 반영한 범위 결정이며 앞선 가설의 효과가 입증된 것으로 기록하지 않는다.

## 확인 기준과 구현 상태

아래는 수용 기준이다. 이후의 코드·화면 관찰 결과와 실제 자동 검사 실행 결과를 구분한다.

| 기준 | 확인할 결과 |
|---|---|
| 홈 복원 | 기존 중앙 월 이동·그라데이션·흰 월 지출·수입 배지와 원래 카드/CTA를 확인한다. 최신 요청에 따라 누적 차트가 월 지출 바로 다음이고 ‘내 소비 한눈에’에 예산·잔여 일수·하루 참고액이 없다. 다른 화면의 새 UI는 유지한다. |
| 전월 비교 | 차트는 당월 같은 경과일, 과거 월 각 월 전체를 비교한다. 미래 날짜·짧은 전월·회계월 시작일·연도 경계, 수집 완료 전월의 실제 0원과 미수집을 구분한다. Hero는 월 전체 기록이므로 당월 차트와 다를 수 있다. 홈 축은 오늘까지 주 곡선과 켜진 범례만 반영하고 다른 화면의 축 기본값은 유지한다. |
| 홈 브리핑과 오늘 내역 | 주간 비교가 없으면 브리핑을 숨기며 CTA/차트의 수집 안내는 독립 유지한다. 오늘 합계·지출 건수와 전체 지출/수입 목록을 표시하며 클릭/롱클릭의 유형·ID를 유지한다. 분석 접기나 오늘 3건 제한은 없다. 예산 계산·설정·차트 토글은 남는다. |
| 내역 조작 | 필터가 켜져도 조건을 다시 열어 수정할 수 있다. X만 초기화한다. 검색/추가/월 이동을 혼동하지 않는다. |
| 거래 행 | 긴 거래명과 100,000,000원 표시에서 금액·상태가 가려지지 않는다. 수입 부호와 통계 제외가 남는다. |
| 작은 모달 | 화면 중앙에 표시되고 대상명·수정·삭제만 담는다. 삭제 취소는 데이터를 변경하지 않는다. |
| 화면 범위 | 홈·내역 목록/달력·대화 목록/방·설정·거래 편집·카테고리/날짜 상세·관리 화면을 각각 확인한다. |
| 접근성 | 휴대폰·폴더블 너비, 글자 1.5배, 라이트·다크에서 겹침·잘림·읽기 어려운 색 조합이 없다. |
| 운영 경계 | 새 AI 호출, DB 스키마, 광고 조건, 동기화·수집 정책 변경이 없다. 가상 거래로만 수정/삭제 검증한다. |

실제 유지율·수익·문자 정확도 개선은 이번 UI 변경만으로 증명되지 않는다. UI 완료 보고는 관찰한 화면과 통과한 검사 범위로 제한한다.

### 첫 금융 UI 정리의 독립 코드·화면 검토

검토자는 기획 담당 에이전트다. `artifacts/finance-ui-refresh-20260908/`의 합성 데이터 화면 PNG를 직접 열어 확인했으며 기기 조작이나 빌드는 하지 않았다.

| 확인한 자료 | 관찰 결과 |

### 첫 금융 UI 정리의 후속 구현 대조

아래 홈 표현은 이후 기존 UI 복원 요청으로 철회한 이력이다. 홈 외의 필터·공용 탭·편집·상세·하단 내비게이션 변경은 유지한다.

홈 제목은 `finance_period_expense`의 ‘이 기간 지출’로 변경했다. 카테고리 제목은 ‘카테고리별 지출’이며, 같은 퍼센트라도 예산을 분모로 할 때는 ‘예산’, 전체 표시 지출을 분모로 할 때는 ‘비중’이라고 표시한다. 브리핑의 기록 기준과 부분 수집 안내는 하단에 유지했다. 필터 버튼/X 분리, 공통 탭과 표준 하단 label 구조도 현재 코드에서 확인했다.

카테고리 상세의 요약 제목·빈 상태도 선택 월과 무관하게 ‘이번 달’을 쓰던 문구를 ‘이 기간’으로 맞췄다. 한국어·영어 문자열을 함께 수정했고 조회나 집계는 바꾸지 않았다. 차트의 비교값 부재 문구는 ‘지난달 비교 금액이 없어요’로 좁혀 지난달 전체 기록이 없다는 오해를 줄인다.

큰 글자 검토에서는 편집 화면의 거래명 아래에 카드 전체 폭으로 금액을 배치하고, 현재 글자 배율에서 부호와 단위를 포함한 실제 폭을 측정하도록 보강했다. `final-editor-amount-dark-large.png`에서는 키보드가 열린 상태에서도 `-2,147,483,647원` 전체가 표시되는 것을 확인했다. Vico 축 라벨은 라이트/다크의 `onSurfaceVariant` 색상을 사용하도록 바뀌었다. 초기 캡처의 제목·축 색상을 최신 구현의 증거로 사용하지 않으며, 후속 로그와 새 캡처는 통합 검증 기록에서 구분한다.

필터 회귀 검사 2개는 중간·최종 실행에서 모두 통과했다. 최종 `android-ui-verified.log`는 메뉴 2개·필터 2개·거래 카드 2개·편집 Hero 1개·달력 2개가 통과했고 수동 fixture 준비 1개는 조건부 스킵되었다. 달력은 320dp의 7열에서 글자 배율 1.5·2와 부호·만/억 단위·정확한 금액의 접근성 설명을 확인한다. 중간 실패와 후속 결과를 혼동하지 않도록 전체 근거는 [통합 검증 기록](07-finance-ui-validation-20260908.md)의 ‘최종 실행 결과’에 모았다.

첫 금융 UI 정리의 최종 캡처에서는 라이트 기본 배율의 홈·대화 목록/방, 다크 큰 글자의 홈·차트·달력, 기본 폴더블 너비의 홈을 독립 확인했다. 달력은 단위가 포함된 금액과 월말까지 스크롤된 상태를 함께 확인했다. 이 관찰 범위에서 추가로 조작을 막는 문제는 발견하지 않았으며, 모든 폴더블 화면이나 실제 AI 응답까지 검증했다고 확대하지 않는다. 이 결과가 다음 홈 집중도 수정까지 검증한 것은 아니다.

### 홈 집중도 후속 수정

이 절은 이후 철회한 접힌 분석 단계의 구현·검증 이력이다. 현재 홈 계약은 마지막 ‘홈 기존 UI 복원과 배치 조정’ 절을 따른다.

이 단계에서는 사용자 피드백을 반영해 `MonthlyOverviewSection`에 ‘기록된 지출’ 총액 하나와 nullable 예산 한 줄을 표시했다. 예산이 없으면 그 줄을 생략하며 0원 예산은 유지했다. 부분 수집/권한 없음 안내는 기본 요약에 남기고, 실제 잔액과의 차이·예산 미설정 경로·주간 근거는 기본 접힘 `HomeAnalysisContent` 안에 보존했다. 수입 → 브리핑 → 현재 월 고정 예상 → 차트 → 카테고리 순서와 과거 월 예산의 현재 설정 기준 안내를 적용했다. 상단 예산 한 줄은 아래 누적 비교 후속 수정에서 상세로 이동했다.

오늘 내역은 월 요약 바로 아래 최신 지출/수입 3건을 표시하고 전체/접기를 제공한다. 지출 합계와 지출 건수의 별도 헤더만 제거하며 실제 거래·필터·통계 계산은 바꾸지 않는다. `showAnalysis`와 `showAllToday`는 월·회계월 시작일·활성 페이지를 키로 접힘 상태를 초기화한다. 코치마크는 숨겨진 차트 대신 `home_details` 분석 진입점을 가리킨다. 이번 코드 대조는 완료했으며 새 빌드/화면 검증은 [통합 검증 기록](07-finance-ui-validation-20260908.md)의 ‘홈 집중도 후속 수정’에서 별도로 관리한다.

### 전월 누적 비교 상단 복원

이 절은 이후 가시성 피드백으로 철회한 통합 카드 단계의 구현·검증 이력이다. 동일 기간 비교와 수집 상태 보정은 유지하지만 현재 표현은 마지막 ‘홈 기존 UI 복원과 배치 조정’ 절을 따른다.

사용자는 지난달과 비교하며 많이 썼는지 확인하는 점을 선호한다고 설명했고 구현을 승인했다. `MonthlyOverviewSection`은 단일 큰 금액 아래 차이 한 문장과 `HomeSpendingComparisonChart`를 같은 카드에 배치한다. 당월은 오늘까지, 과거 월은 각 월 전체를 비교하며 `HomeSpendingComparison`이 미래 날짜 기록과 짧은 전월의 경계를 처리한다. 현재·전월 수집 상태를 확인해 비교 가능할 때만 더/덜 쓴 금액을 표시하고 전월 실제 0원도 금액 차이로 비교한다. 수집 미완료 전월 선은 보이지 않는다.

상단은 두 곡선과 해당 연·월 범례만 두고 오늘 3건·접힌 분석 구조를 유지한다. 예산·수입·주간·예상·카테고리 및 3/6개월 평균·예산 토글은 상세에 남는다. 상단과 상세 차트는 같은 `HomeSpendingTrendInfo`를 재사용하되 상단 축은 보이는 두 곡선만으로 정한다. 상세 예산과 카테고리의 월 전체 기록 집계는 유지하므로 미래 날짜 거래가 있으면 상단 오늘까지 금액과 다를 수 있다. 코드 대조는 완료했고 이번 변경의 새 검증 결과는 [통합 검증 기록](07-finance-ui-validation-20260908.md)의 ‘전월 누적 비교 상단 복원’에서 따로 관리한다.

이번 Home JVM 56개와 UI 7개의 성공 로그를 대조했다. 기본 라이트·다크 큰 글자·과거 월의 실제 앱 캡처와 DB를 바꾸지 않는 400dp 거래 3건 fixture를 독립 확인했다. 관찰한 범위에서 상단 금액/비교/곡선과 오늘 내역·분석 진입의 새 차단 문제는 보이지 않았다. 실제 앱의 오늘 0건 화면을 거래가 많은 상태의 검증으로 확대하지 않는다.

### 지출 가시성 재조정

이 절 역시 이후 기존 UI 복원 요청으로 철회한 표현의 이력이다. 이전 자동 검사와 배치 측정 결과를 현재 복원 UI의 검증으로 사용하지 않는다.

사용자는 통합 카드가 어제 작업 전과 비슷하고 지출 가시성이 오히려 낮다고 피드백했다. 기존 자동 검사와 잘림 확인은 이 체감 문제를 해결했다는 근거가 될 수 없다. `MonthlyOverviewSection`은 차트/비교 문장을 제거하고 `primaryContainer`의 독립 지출 영역을 표시한다. `HomeExpenseAmount`는 42sp 숫자와 0.55em 통화 단위를 사용하며 큰 글자·긴 금액을 실제 폭에 맞춰 필요한 만큼만 축소한다.

바로 아래 새 `HomeComparisonSection`은 중립 문장과 기본 120dp/큰 글자 160dp의 두 곡선을 보여준다. 채움·별도 총액을 제거해 보조 정보로 구분하고 비교에 추가 펼침을 요구하지 않는다. 오늘 3건과 접힌 분석, 동기간/과거 전체·수집 상태·0원·미래 날짜·축 계산은 유지한다. 코드 대조를 마쳤으며 같은 금액·화면 조건의 전후 캡처와 새 실행 결과는 [통합 검증 기록](07-finance-ui-validation-20260908.md)의 ‘지출 가시성 재조정’에서 관리한다. 사용자 체감 개선 여부는 사용자 확인 전 확정하지 않는다.

최종 APK의 빌드와 UI 8개 통과 로그, 기본·다크 큰 글자·합성 3건 캡처를 독립 확인했다. 긴 금액은 재측정으로 한 줄 표시를 보강했고 큰 글자 비교 문장은 짧은 한국어 문구와 균형 잡힌 줄바꿈을 적용했다. 직전 통합 카드 대비 금액 영역은 커졌으며 기본 화면의 오늘 내역은 44px 올라갔다. 다크 큰 글자에서는 9px 내려가므로 모든 조건에서 위치가 개선됐다고 주장하지 않는다. 관찰한 기본·다크 화면 모두 금액과 비교 곡선·범례는 첫 화면에 남는다.

### 홈 기존 UI 복원과 배치 조정

사용자는 그라데이션을 포함해 UI 정리 전 600996a의 홈으로 되돌리기를 요청한 뒤, 누적 차트를 ‘이번 달 지출’ 바로 아래로 올리고 ‘내 소비 한눈에’에서 예산을 빼도록 지시했다. 홈의 색상·Typography와 거래 카드/CTA를 전용 구현으로 복원해 다른 화면의 새 스타일을 유지한다. 중앙 월 이동·월 전체 지출/수입 배지 → 누적 차트 → 최근 소비 비교만 남긴 브리핑 → 현재 월 고정 예상 → 카테고리 → 오늘 합계·지출 건수·전체 거래가 현재 순서다. 주간 비교가 없으면 브리핑 카드를 숨긴다.

별도 상단 비교 카드·분석 토글·3건 제한·`BriefingBudgetSection` UI를 제거했다. 예산 서비스·계산·설정·차트의 양수 예산선은 유지하며 DB·수집·AI·광고 정책은 바꾸지 않는다. 32sp 기본 금액은 폭 측정·재측정으로 긴 금액을 한 줄에 표시한다. 차트에는 동일 경과일·미래 날짜 제외·과거 월 전체·전월 수집 상태·실제 0원·연월 범례·X축 보정을 유지한다. Hero는 월 전체 기록, 당월 차트는 오늘까지 기준이라는 차이를 보존한다. 홈 차트만 켜진 곡선 기준으로 Y축을 맞추며 공통 기본 동작은 유지한다.

앞선 홈 개편 검증은 철회 이력으로 보존하고 이번 복원의 새 결과는 [통합 검증 기록](07-finance-ui-validation-20260908.md)의 ‘홈 기존 UI 복원과 배치 조정’에 따로 기록한다. 축 보정 뒤 빌드 성공·JVM 56개(Home 51 + 축 5)·UI 8개 통과를 독립 대조했다. 기본·다크 큰 글자·주간 브리핑·예산 ON/OFF와 별도 합성 fixture의 PNG도 직접 확인했다. 관찰 범위에서 최신 순서와 예산 제외, 기록 안내 유지에 추가 차단 문제는 보이지 않으며 모든 기기나 사용자 체감 개선을 검증했다고 확대하지 않는다.
