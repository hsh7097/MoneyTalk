# 금융 UI 정리 기준

## 조사 범위와 선택 이유

2026-09-08에 토스의 공식 TDS 문서와 플랫폼 디자이너 글, 뱅크샐러드 공식 서비스 소개를 확인했다. 로그인한 경쟁 앱의 실제 화면 전체를 직접 조작한 검증은 아니다. 마케팅 페이지를 현재 앱의 정확한 스펙으로 간주하지 않는다.

- [TDS Colors](https://tossmini-docs.toss.im/tds-mobile/foundation/colors/)는 명명한 회색 단계와 배경 역할을 제공한다. 이 공개 기준은 9월 8일 UI 정리의 참고 자료다. 2026-09-09 최신 요청에 따라 MoneyTalk의 색상은 일주일 전 팔레트로 복원하며, 현재 기능과 화면 배치를 유지한다. 아래 색상값은 MoneyTalk의 선택이며 토스 규격을 복제한 것이 아니다.
- [TDS Typography](https://tossmini-docs.toss.im/tds-react-native/foundation/typography/)는 크기와 굵기 조합을 일관된 체계로 취급한다. MoneyTalk는 금액, 제목, 본문, 보조 정보의 순서를 분리하고 기존 시스템 폰트를 유지한다.
- [TDS ListRow](https://tossmini-docs.toss.im/tds-react-native/components/list-row/)의 좌측·중앙·우측 영역 구조를 참고한다. 거래행에서는 카테고리 아이콘, 거래명/설명, 금액을 같은 축에 맞춘다.
- [토스 디자인 시스템 개선](https://toss.tech/article/toss-design-system)은 긴 문구, 폴드 화면, 큰 글자, 다크 모드, 아이콘 대체 텍스트를 컴포넌트 기준에 포함한다. MoneyTalk도 기본 상태뿐 아니라 큰 금액과 긴 거래명에서 금액을 다음 줄로 이동한다.
- [토스 디자인 시스템 가이드](https://toss.tech/article/toss-design-system-guide)의 큰 구조부터 세부 상태를 정의하는 방식을 참고해 색·간격·행 규격을 화면별 구현 전에 합의했다.
- [뱅크샐러드 서비스 소개](https://go.banksalad.com/introduce_services/)와 [공식 홈](https://www.banksalad.com/)은 금융 정보를 서비스별로 묶어 설명한다. MoneyTalk에서 가져올 원칙은 목적별 정보 묶음이며 대출·보험·건강 기능이나 홍보 배너를 추가하는 것은 이번 범위에 포함하지 않는다.

## 시각 토큰

복원 기준은 2026-09-02까지 존재한 최신 조상 `9b4b4bf`(2026-07-13)다. 날짜에 맞는 새 디자인을 추정하지 않고 해당 커밋의 `Color.kt`, `Theme.kt`, `FriendlyMoneyColors.kt` 역할을 따른다. 이후 추가한 주간 근거·차트 날짜 선택·가계부 요약 접힘과 현재 섹션 순서는 유지한다.

|---|---|---|
| 앱 배경 | `#F9FAFB` | `#171A1E` |
| 카드/모달 표면 | `#FFFFFF` | `#252A30` |
| 보조 표면 | `#F3F4F6` | `#2D3239` |
| 주요 텍스트 | `#111827` | `#ECECEC` |
| 보조 텍스트 | `#6B7280` | `#6B7684` |
| 세 번째 텍스트 | `#9CA3AF` | `#4A5568` |
| 주요 액션 | `#1B2838` | `#4CAF50` |
| 수입 금액 | `#137FEC` | `#3AC977` |
| 지출 금액 | `#EF4444` | `#EF4444` |
| 액션 위 텍스트 | 흰색 | 흰색 |

일반 거래 금액은 수입 라이트 파랑·다크 초록, 지출 빨강과 부호를 함께 사용한다. 통계 제외 거래의 금액은 보조색으로 낮추고 제외 태그를 유지한다. 고정 태그는 Coral `#FF6B5B`를 사용한다. 홈의 그라데이션 금액과 편집 유형색은 아래 전용 표현을 따른다. 삭제·오류·예산 초과 안내는 위험 색상을 유지한다. 달력의 주말과 여러 카테고리를 비교하는 차트 색상은 의미 구분에 필요하므로 단색으로 합치지 않는다.

`Theme.kt`는 원래 `colorScheme`/`moneyTalkColors` 역할을 제공한다. 이후 추가했던 `surfaceContainer*`, inverse, `surfaceTint` 지정은 제거해 기준 커밋처럼 Material 3 기본값을 사용한다. `Navy*`와 다크 Green/Orange 역할을 복원하고 `FriendlyMoneyColors`도 크림 `#FFF7EA`, 민트 `#43B883`, 진한 민트 `#1F7A53`, 원래 라이트·다크 카드/글자 getter를 사용한다. `MoneyTalkTheme`의 시스템 바 처리와 Typography 선택 구조는 바꾸지 않는다.

9월 8일 개편 당시 색상 조합을 수식으로 확인한 대비는 라이트 보조 텍스트/흰 표면 5.42:1, 라이트 버튼/흰 글자 5.00:1, 다크 보조 텍스트/카드 7.92:1, 다크 버튼/글자 7.53:1이다. 이는 당시 불투명 토큰 조합의 과거 계산 결과로, 이번에 복원하는 팔레트의 대비나 접근성 검증 결과가 아니다. alpha나 별도 고정 색상을 적용하는 화면의 이번 복원 결과는 아래 후속 검증 기록에서 구분한다.

## 공통 렌더링 계약

- `TransactionCardCompose`의 `Info`, `onClick`, `onLongClick` 계약은 유지한다. 데이터 수정 로직을 공통 UI에 넣지 않는다. 홈은 같은 Info와 콜백을 받는 `HomeTransactionCard`로 공용 화면과 표현을 분리한다.
- 거래명과 금액을 첫 줄에, 카테고리·시간·카드명을 그 다음 줄에 표시한다. 메타데이터는 최대 두 줄까지 허용한다. 메모는 기존처럼 거래명 옆에 보조 색상으로 남긴다.
- 글자 배율 1.3 초과, 카드 폭 320dp 미만 또는 표시 금액 12자 초과이면 금액을 별도 줄로 옮긴다. 긴 거래명은 이 상태에서 두 줄까지 표시한다.
- 고정·통계 제외 상태는 메타데이터와 별도 행으로 두고 줄바꿈을 허용한다. 고정 태그는 Coral, 통계 제외 금액은 보조색을 사용한다. 공간 부족으로 제외 상태가 사라지지 않게 한다.
- 설정 부제목을 빈 공백으로 채우지 않는다. 제목과 부제목의 길이를 제한하지 않고 행이 세로로 늘어나게 한다. 일반 아이콘은 `primary`, 부제목은 `onSurface` 60%, 화살표는 `onSurface` 30%를 사용하며 위험 행은 `error`를 유지한다.
- 탭의 선택 색상은 기존 `SegmentedTabInfo`를 존중한다. 선택 면의 색상만 기존 테마 역할로 복원한다. callback의 index, 현재 선택 상태, 필터 의미는 바꾸지 않는다.
- 하단 `NavigationBarItem`의 선택 아이콘/글자는 `onSurface`, 비선택 아이콘/글자는 `onSurface` 50%, indicator는 `surface`를 사용한다. 표준 아이콘·label, 기존 route/재클릭/IME 정책은 유지한다.
- 그룹 헤더와 거래행의 일반 지출 색상이 일치해야 한다. 수입과 지출은 기호와 의미 색상으로 함께 구분한다.

- `ImportDataCtaSection`/`FullSyncCtaSection`은 현재 24dp 반지름·20dp 내부 여백을 유지하며 `FriendlyMoneyColors.elevatedCardBackground`, `textPrimary`/`textSecondary`를 사용한다. 진행/진입 표시는 가져오기 Coral, 전체 기간 Mint, 부분 기간 Honey를 사용한다. 부분 수집/광고 유무별 기존 문구와 동기화 중 입력 차단을 보존하며 설명 줄 수를 제한하지 않는다.
- `CumulativeTrendSection`의 두 오버로드는 기본 24dp/20dp 중립 카드에 같은 제목 위계를 사용한다. 금액은 확대 가능한 16sp 보조 정보로 표시한다. Info 오버로드의 `showCard` 기본값은 true이며 홈에서만 false로 원래 카드 없는 배치·큰 누적 금액을 표시한다. `scaleToVisibleLines` 기본 false는 전체 곡선 기준 Y축을 유지하며 홈만 true로 오늘까지 주 곡선·켜진 비교선을 반영한다. 데이터·토글 상태·애니메이션을 유지하고 범례는 48dp 높이와 체크 상태 접근성을 제공한다.
- `VicoCumulativeChart`의 시작축·하단축 라벨은 모두 `MaterialTheme.colorScheme.onSurfaceVariant`를 사용한다. 라이트/다크에서 축 글자가 별도 고정 회색으로 남지 않게 한다. X축 원점과 누적 배열을 맞춰 0원부터 `daysInMonth`까지 표시하고 중간 라벨을 경과일 인덱스와 일치시킨다.
- 홈의 별도 보조 비교 차트를 제거하면서 미사용 `VicoCumulativeChart.showAreaFill` 옵션도 제거했다. 현재 차트는 원래 영역 채움을 사용한다.
- `TransactionHeroCard`의 거래명은 아이콘 옆에서 최대 세 줄을 사용하고 금액은 그 아래 카드 전체 폭에 독립 배치한다. `EditableHeroAmount`는 사용자 글자 배율에서 부호·천 단위·원 단위를 포함한 실제 표시 폭을 측정해 필요할 때만 글자를 줄인다. 입력/표시 전환에도 앞자리와 부호가 가로 스크롤 밖으로 밀리지 않게 하며 입력값은 그대로 유지한다. 거래 유형 색상은 `TransactionType.accentColor()`가 지출 `FriendlyMoneyColors.Coral`, 수입 `FriendlyMoneyColors.Mint`, 이체 `FriendlyMoneyColors.Sky`로 구분한다.
- 달력의 `CalendarAmountText`는 7열 안의 실제 셀 폭과 글자 배율로 금액을 측정해 부호·만/억 단위가 함께 남도록 표시 크기를 맞춘다. 정확한 원 단위 금액은 접근성 설명에 유지하며, 날짜 선택을 통해 기존 상세 내역으로 이동한다. 축약 표시의 가독성과 큰 글자 배율의 균형은 실제 셀에서 검증한다.

## 홈 기존 UI 복원 기준

사용자는 후속 홈 개편을 철회하고 그라데이션을 포함한 600996a의 기존 홈 UI 복원을 요청했다. 추가로 누적 차트를 ‘이번 달 지출’ 바로 아래로 옮기고 ‘내 소비 한눈에’에서 예산을 빼도록 지시했다. 최신 순서는 CTA → 중앙 월 이동/그라데이션 지출·수입 → 누적 차트 → 최근 소비 비교 → 카테고리 → 오늘 전체 내역 → 고정 예상이다. 앞선 독립 42sp 금액·보조 두 곡선·접힌 분석은 현재 기준이 아니며 검증 이력만 보존한다.

`HomeTheme`은 홈 내부에만 기존 MaterialTheme·MoneyTalk 확장 색상·숫자 Typography를 적용한다. `HomeColors`와 `HomeTransactionCard`/`HomeImportDataCta`/`HomeFullSyncCta`는 원래 홈의 테두리·색상·카테고리 칩을 제공한다. 앱 테마 선택과 시스템 바 처리, 내역·상세·편집·채팅·설정의 현재 배치를 유지하면서 공통 색상도 같은 복원 기준을 따른다. 홈 화면 여백은 원래 16dp이며 그라데이션은 `#1F7A53`·`#43B883`·`#F4B740` 조합이다.

`MonthlyOverviewSection`은 월 전체 지출과 수입 배지를 표시한다. `HomeExpenseAmount`는 32sp 기본 크기와 숫자/통화 단위가 같은 크기인 중앙 정렬을 유지한다. 최신 복원 요청에 따라 그라데이션 위 큰 금액은 `Color.White`, 수입 배지 글자는 흰색 80%, 점은 흰색 50%를 사용한다. 현재 글자 배율에서 1px 여유 폭을 측정해 필요한 만큼 비례 축소하고, 축소 결과도 재측정해 넘치면 0.5sp씩 낮춘다. 홈 거래 카드도 기본 배치는 복원하되 큰 글자·좁은 폭·긴 금액일 때 금액을 다음 줄로 옮기고 메타데이터 줄바꿈을 유지한다.

차트는 `SpendingTrendSection(showCard = false, scaleToVisibleLines = true)`를 통해 원래 카드 없는 배치·큰 누적 금액·영역 채움·전월/평균/예산 토글을 사용한다. wrapper와 공통 차트의 기본 true는 다른 화면에 유지한다. 별도 상단 비교 컴포넌트와 전용 Y축 계산은 제거하지만 당월 동일 경과일·미래 날짜 제외·과거 월 전체·전월 수집 상태·실제 0원·연월 범례·Vico X축 보정은 유지한다. Hero는 월 전체 기록, 당월 차트는 오늘까지이므로 미래 날짜 기록이 있으면 값이 다를 수 있다.

‘내 소비 한눈에’는 주간 비교가 있을 때만 기록 기준/부분 수집 안내와 최근 소비 비교를 표시한다. 예산·잔여 일수·하루 참고액 UI와 미사용 `BriefingBudgetSection`은 제거했으며 예산 계산·설정·차트의 양수 예산선은 유지한다. 브리핑이 숨겨져도 CTA·차트의 수집 상태 안내는 독립적으로 남는다. 오늘 목록은 합계·지출 건수와 전체 지출/수입을 표시하고 분석 접기는 사용하지 않는다.

복원한 색상과 최신 요청의 순서·예산 제외, 금융 비교 경계, 다른 화면의 기능·배치 유지 여부를 검증한다. 이전 홈 개편의 자동 검사나 시각 측정값을 이번 복원의 성공 또는 사용자 체감 개선 근거로 사용하지 않는다.

## 검증 경계

이번 복원은 `IncomeLight`/`IncomeDark`, 공통 `ExpenseColor`와 `moneyTalkColors`를 기준으로 한다. `ExpenseLight`/`ExpenseDark`는 같은 `ExpenseColor`를 가리키는 호환 이름이다. 일반 거래와 날짜별 합계는 공통 역할을 따르며 통계 제외·홈 그라데이션·편집 전용 유형색은 위 예외를 유지한다. 주간 비교는 최근 지출색과 이전 보조색, 기간 레이블·날짜로 구분한다. 월 지출 그라데이션과 누적 차트의 월·평균 곡선 색, 주간 근거 이동·차트 터치·가계부 접힘 기능은 유지한다.

직전 수입 빨강·지출 파랑 개편의 과거 대비 계산은 라이트 흰 카드에서 수입 5.57:1·지출 6.02:1, 다크 카드 `#20252B`에서 수입 7.23:1·지출 7.15:1이었다. 당시 4.5:1 대비 계약을 현재 팔레트의 성공 조건으로 사용하지 않는다. `TransactionSemanticPaletteTest`의 기존 두 검사는 기준 커밋의 금액 원색과 라이트·다크 표면/액션 값으로 갱신한다. `TransactionSemanticColorsTest`는 공용/홈 및 통계 제외 거래, 흰 그라데이션 금액/수입 배지의 실제 색 연결을 확인할 대상이다. 이번 색상 복원의 실행 결과는 [후속 통합 검증 기록](08-home-ledger-ux-validation-20260909.md)의 색상 복원 절을 따른다. 과거 통과 기록으로 대신하지 않는다.

9월 8일 공통 UI 작업자는 소유 파일의 변경 내용을 다시 읽고 색 대비와 변경 줄 공백을 확인했다. 빌드·자동 검사·화면 검증은 통합 담당자가 실행하고, 실행 로그·합성 데이터 캡처를 기획 담당자가 독립 대조했다. 실제 통과 결과와 후속 검증 상태는 [금융 UI 통합 검증 기록](07-finance-ui-validation-20260908.md)이 정본이다. 기능 저장/검색/동기화 정책, DB 스키마, AI 호출과 광고 조건은 이 공통 UI 작업에서 변경하지 않는다.

통합 확인 대상은 홈, 내역 목록/달력, 카테고리 상세, 날짜 상세, 설정, 빠른 작업 모달, 기존 편집 화면이다. 라이트·다크, 기본·큰 글자, 긴 거래명·큰 금액, 고정/통계 제외, 수입/지출, 터치/롱클릭을 함께 확인한다.
