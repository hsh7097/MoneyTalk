# 금융 UI 통합 검증 기록

이 문서는 [디자인 기준](05-finance-ui-design-system-20260908.md)과 [사용성 감사](06-finance-ux-plan-20260908.md)에 따른 구현을 검증한 기록이다. 실제 실행 결과와 코드 확인, 정지 화면 관찰을 구분한다. 사용자 유지율이나 수익 개선을 검증한 실험은 아니다.

홈은 이후 사용자 요청으로 기존 그라데이션 UI를 복원하고 차트 위치·브리핑 예산 표시를 조정했다. 아래 초기 UI와 홈 집중도·통합 비교·가시성 재조정은 철회한 홈 표현의 검증 이력이다. 다른 화면의 변경은 유지하며 현재 홈의 범위와 새 결과는 마지막 ‘홈 기존 UI 복원과 배치 조정’ 절을 따른다.

## 작업 기준

- 기존 작업은 `e29ea4b`, `e4cb526`, `f19142f`, `0b6b9c6`, `9e29609`, `7fca5ca`, `600996a`의 7개 커밋으로 분리된 뒤 금융 UI 변경을 시작했다.
- 이번 변경 기준 브랜치는 `codex/finance-ui-refresh`이며, 아래 결과는 해당 작업 트리와 명시된 실행 자료에 대한 기록이다. 이후 커밋·배포·실기기 설치를 자동으로 의미하지 않는다.
- 통합 담당자는 새 UI 변경을 미커밋 상태로 남겨 검토할 수 있게 했으며 푸시하지 않았다. 사용자 요청에 따른 기존 작업 7개 커밋과 이번 새 UI 변경을 구분한다.
- 첫 통합 단계에서는 통합 담당자가 에뮬레이터에서 합성 거래로 조작·캡처했다. 기획 검토자는 소스·로그·PNG를 독립 대조했으며 사용자 실기기나 경쟁 앱의 실제 계정을 직접 조작하지 않았다. 이후 통합 담당자의 실기기 검증은 마지막 별도 절에 기록한다.
- 자료 경로는 저장소 기준 `artifacts/finance-ui-refresh-20260908/`다. 이 로컬 검증 자료가 버전 관리에 포함되어 있다고 가정하지 않는다.

## 홈 기존 UI 복원과 배치 조정

사용자는 앞선 홈 개편을 철회하고 그라데이션을 포함한 600996a의 기존 UI 복원을 요청했다. 이어 누적 차트를 월 지출 바로 아래로 옮기고 ‘내 소비 한눈에’에서 예산을 제거하도록 지시했다. 현재 홈은 CTA → 중앙 월 이동/그라데이션 월 전체 지출·수입 → 카드 없는 누적 차트 → 최근 소비 비교 → 현재 월 고정 예상 → 카테고리 → 오늘 합계·지출 건수·전체 내역 순서다. 주간 비교가 없으면 브리핑을 숨기며 예산 계산·설정·차트 토글은 유지한다. `HomeTheme`/`HomeColors`와 홈 전용 거래 카드/CTA는 다른 화면의 새 스타일과 분리한다. 분석 접기·별도 상단 비교·3건 제한·예산 브리핑 UI는 제거했다.

금액은 원래 32sp·흰색·동일 크기 통화 단위로 복원하면서 긴 금액의 폭 측정·재측정을 유지한다. 당월 차트 동일 경과일/미래 날짜 제외, 과거 월 전체, 전월 수집 상태와 실제 0원, 연월 범례·Vico X축 보정은 남긴다. Hero의 월 전체 기록과 당월 차트 오늘까지 금액은 범위가 다를 수 있다. 홈에서만 켜진 곡선과 오늘까지 주 곡선에 맞춰 Y축을 조정하고 공통 기본값은 유지한다.

이번 자료는 `artifacts/home-restored-20260908/`에 있다. 기획 담당자가 최종 소스·로그·JVM XML 합계와 아래 PNG를 독립 대조했다. 앞선 홈 개편의 성공 기록과 이번 복원 결과를 구분한다.

초기 `build.log`는 `HomeColors.MintDeep`의 private 접근 오류로 실패했으며 수정 후 `build-verified.log`의 앱·검사 APK 및 Home JVM 51개가 성공했다. 초기 `ui-tests.log`는 UI 8개 통과(10.654초)였지만 실제 화면에서 꺼진 100만원 예산선과 기존 최소축 때문에 62,500원 지출선이 바닥에 눌리는 문제가 관찰됐다. 홈만 `scaleToVisibleLines = true`와 `visibleTrendAxisMax`의 1/2/5 올림을 사용하도록 보정했다. 공통 기본 false는 전체 곡선과 기존 축 정책을 유지한다. 다음 표가 이 축 보정까지 반영한 최종 결과다.

## 실기기 홈 후속 검증

통합 담당자는 실제 Fold7의 Android 16, 접힌 화면 1080×2520/density 420, 글자 1.0배·다크 모드에서 홈 동선을 조작했다. 기존 서명을 유지한 광고 제외 release `versionCode 22`를 업데이트 설치(`-r`)했으며 월 지출·수입과 월 시작일 19일 기준 기간이 설치 전후 같음을 확인했다. 자료는 로컬 `artifacts/physical-home-20260908/`에 보관한다. 개인 거래명·실제 금액·기기 식별자는 이 추적 문서에 옮기지 않으며 개인 내역이 포함된 PNG/XML을 문서에 삽입하지 않는다.

|---|---|---|

실제 오늘 목록의 끝에서 ‘맨 위로’ FAB가 마지막 거래 금액을 가리는 문제를 `today-bottom.png/xml`에서 발견했다. `HomePageContent`의 `LazyColumn.contentPadding`을 위 16dp·아래 80dp로 조정해 마지막 행을 FAB 위로 스크롤할 수 있는 공간을 확보했다. 좌우 여백·거래·집계 계산은 바꾸지 않는다.

하단 여백까지 반영한 최종 `build-personal-release.log`에서 `assembleDebug`와 `assembleRelease`가 3분 54초에 성공했고 `install-final.log`에서 업데이트 설치 성공을 확인했다. `home-final.png/xml`은 기존 그라데이션 → 차트 → 예산 없는 브리핑 배치와 설치 전후 동일한 월 지출·수입·기간을 확인한 자료다. 초기 6분 10초 빌드는 `build-before-padding.log`로 보존하며 최종 수정본의 근거와 구분한다.

통합 담당자는 같은 실기기의 `today-bottom-fixed.png/xml`을 직접 확인했다. 마지막 거래 금액의 Y1936–1992, 카드 하단 Y2058과 FAB 영역 Y2101–2227이 분리돼 금액이 버튼에 가려지지 않는다. 기획 담당자는 개인정보 텍스트를 출력하지 않고 XML의 배치 좌표와 최종 빌드·설치 로그를 대조했다. 이번 실기기 검증에서는 거래 저장·삭제를 실행하지 않았으며 확인한 접힌 화면·기본 글자 배율의 동선에 범위를 한정한다.
