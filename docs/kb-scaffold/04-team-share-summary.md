# 팀 공유용 KB 스카폴드 요약

> 역할:
> - 팀 공유/온보딩 때 먼저 읽히는 1페이지 요약이다.
> - 상세 규칙 대신 왜 만들고 무엇만 최소로 만들지 빠르게 설명한다.
> - 팀 공유 문구가 바뀌면 상세 정본 문서와 충돌하지 않는지 확인한다.

이 문서는 MoneyTalk KB 스카폴드를 공유할 때 먼저 읽히는 1페이지 요약이다.
상세 규칙은 [README.md](README.md), 작성 원칙은 [01-principles.md](01-principles.md), 실제 작성 순서는 [03-authoring-workflow.md](03-authoring-workflow.md)를 기준으로 한다.

## 왜 만드는가

KB의 목적은 사람이 읽을 긴 설명서를 만드는 것이 아니라, AI가 현재 코드 구조를 기준으로 필요한 문서만 골라 읽고 수정 위치를 빠르게 찾게 만드는 것이다.
루트 문서는 판단과 라우팅을 담당하고, 도메인/기능/서브모듈 문서는 선택된 뒤의 실행 상세를 담당한다.

## 최소로 만들 것

새 도메인, 기능, 서브모듈 패키지는 작게 시작한다.

| 파일 | 역할 |
|---|---|
| `README.md` | 기준 코드 경로, 먼저 볼 문서, 핵심 파일, 현재 생략한 확장 문서를 안내한다. |
| `change-log.md` | 어떤 코드/diff/검증을 근거로 KB를 만들거나 바꿨는지 남긴다. |

KB 루트에는 기존 MoneyTalk 관례대로 `README.md`, `00-agent-routing.md`, `00-change-index.md`, `01-structure-map.md`를 둔다.
패키지 내부 `00-structure-map.md` 또는 `01-structure-map.md`, `05-file-inventory.md`, `package-reference/`는 파일 수가 많거나 AI가 수정 위치를 반복해서 놓칠 때 확장한다.

## 반드시 지킬 것

- 현재 코드와 실제 diff로 확인한 사실만 쓴다.
- 없는 코드 경로, 없는 문서, 미확인 패키지는 추정해서 링크하지 않는다.
- PRD, 개발 스펙, 미래 마이그레이션 목표는 현재 구현 KB에 섞지 않는다.
- 후속 설계가 필요하면 `미구현` 또는 `후속 설계`로 명확히 표시한다.
- 도메인 KB, 기능 KB, 서브모듈 KB의 책임을 섞지 않는다.
- 공통 작성 규약이나 빌드 차단 규칙은 `AGENTS.md` 또는 루트 공통 문서에 두고, KB에는 구현 위치와 링크만 둔다.

## 작성 순서

1. 대상이 도메인인지, 기능인지, 서브모듈인지 정한다.
2. 실제 source root와 대표 파일이 존재하는지 확인한다.
3. 대상 패키지 `README.md`와 `change-log.md`를 먼저 만든다.
4. 루트 `00-agent-routing.md`에 변경 파일 경로와 읽을 문서를 연결한다.
5. 복잡도가 확인된 경우에만 구조 지도, 파일 인벤토리, package-reference를 확장한다.
6. 샘플 작업으로 AI가 필요한 문서와 수정 파일을 찾는지 검증한다.

## 공유 전 확인

| 질문 | 통과 기준 |
|---|---|
| 루트 README만 읽고 하위 문서 위치를 알 수 있는가? | 도메인/기능/서브모듈 목록과 먼저 볼 문서가 있다. |
| 작은 패키지에 확장 문서를 강제하지 않았는가? | `README.md + change-log.md`만으로 시작할 수 있다. |
| 현재 코드 근거가 있는가? | source root, 핵심 파일, 기존 문서 또는 diff가 실제로 확인됐다. |
| AI가 선택적으로 읽기 좋은가? | 전체 문서를 읽지 않아도 작업 경로로 필요한 문서가 좁혀진다. |
| 검증 기록이 있는가? | 샘플 작업 결과 또는 다음 검증 항목이 `change-log.md`에 남아 있다. |

샘플 작업 검증 전 문서는 `verified`가 아니라 `draft`로 공유한다.
이 경우 공유 문구에는 “스카폴드 기반 초안이며, 실제 샘플 작업 검증 전까지는 현재 코드로 재확인한다”는 전제를 붙인다.
